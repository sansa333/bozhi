## 仍需真实业务配置才能验收

1. 当前记账主体。原材料及参考项目没有提供可靠的记账主体配置；不能根据平台名、邮件发件人或 Logo 猜测。AR/AP 的代码逻辑有测试，但尚未得到真实主体的业务确认。
2. 用户材料的可访问下载地址。远程 OCR 只能下载公网 URL；参考项目没有该托管配置。目前原始材料只做了本地解析和真实模型提取，没有伪称已通过指定 OCR 完整识别。
3. 指定 OCR 的完整字段说明。公开测试返回的是结构化对象，不含原始 OCR 文字。真实费用的正负号、税额、付款方式和 chargeList 字段需要用业务样例确认。当前结构化模式自动要求原件复核。
4. 已有真实账单 JSON。更新逻辑在合成样例中验证，没有提供真实旧账，因此不能声称已完成历史账单对账。
5. 个别字段仍有歧义，例如邮件只写 `$50`，币种保持 null；通知的合计引文不充分时保留待审核。金额提取通过不等于这些字段已确认。

## 复现

```powershell
uv sync --frozen --extra dev
uv run pytest -q
uv run ruff check src tests scripts
uv run python scripts/demo.py
uv run shipping-agent run '<材料目录>' --ocr-mode local --out output/materials-live.json
uv run python scripts/evaluate_materials.py output/materials-live.report.json
```
